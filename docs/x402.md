# x402 pool assessment (Base Sepolia only)

`GET /assess` is a local HTTP wrapper around the existing `assess_pool` result. It is the only paid route. It does not expose MCP, raw pool resolution, wallet functions, trading signals, or any other service.

The server uses x402 v2 packages (`@x402/express`, `@x402/core`, `@x402/evm`) with the official test facilitator `https://x402.org/facilitator`. It accepts only `exact` payment requirements on Base Sepolia (`eip155:84532`) for `$0.001`.

## Receiver configuration

The checked-in public receiver configuration is [`config/assess-x402.mjs`](../config/assess-x402.mjs):

- `payTo`: `0xcED7757fb07449f2f20AB673255fEc480104c54A` (the dedicated public x402 receiver chosen by the owner; it is separate from the trading wallet)
- network: `eip155:84532` only
- price: `$0.001` only
- facilitator: `https://x402.org/facilitator` only

It contains no private key. `ASSESS_PAY_TO` may override the recipient only with another nonzero public EVM address; the server rejects any malformed value. No server-side private key is accepted or needed.

## Local supervised run

Install dependencies once in this checkout, inject `THEGRAPH_TOKEN` through your secret manager into the process environment, then run the process in the foreground. It is hard-locked to `127.0.0.1:4021` by default; `ASSESS_HOST` rejects wildcard, public, hostname, and IPv6 bindings.

```sh
npm ci
npm run start:x402
```

`THEGRAPH_TOKEN` stays only in the server process environment. It is used after a successful payment only by the existing bounded Substreams and Base Token API calls. It is never sent to the facilitator or HTTP caller. Do not paste it into shell history, repository files, client request headers or logs. An owner-only secret-store file may be used to populate the process environment.

Optional public-only runtime configuration:

```sh
ASSESS_PORT=4021 \
ASSESS_PAY_TO=0xcED7757fb07449f2f20AB673255fEc480104c54A \
npm run start:x402
```

Stop the foreground server with `Ctrl-C`. There is no background service, public listener, deployment, or persistent payer process.

## Unpaid request: expected 402

With the local server running, use an in-window Base pool id:

```sh
curl -i --max-time 10 \
  'http://127.0.0.1:4021/assess?network=base&pool_id=0xPOOL_ID_FROM_THE_CONFIGURED_WINDOW'
```

Expected result: `HTTP/1.1 402` and a `PAYMENT-REQUIRED` header describing only `exact`, `$0.001`, `eip155:84532`, and the configured public `payTo`. The assessment resolver must not run on this request.

Only `GET /assess` is permitted. `HEAD`, `POST`, `PUT`, `PATCH`, `DELETE`, and `OPTIONS` return `405 Allow: GET` before x402 or assessment work. Malformed `PAYMENT-SIGNATURE` input is rejected by x402 before assessment. A valid payment must also be followed by a valid 32-byte `pool_id` and `network=base` or `network=robinhood`; the lookup remains restricted to the preconfigured bounded window.

## Owner-run Base Sepolia paid acceptance

This is the reproduction procedure for an explicitly owner-approved testnet payer round. The recorded successful round is linked above. Starting the server alone does not authorize a payment.

Before the round, the owner must independently confirm all of the following:

1. The URL is exactly the loopback `/assess` URL above; no public host or tunnel.
2. The first response is 402 and its requirements are exactly `exact`, `$0.001`, `eip155:84532`, and the configured recipient above.
3. The buyer uses a separate Base Sepolia test wallet with test USDC only. Its key remains in that buyer environment/secret store, never in this repository or the server environment.
4. The buyer approves one testnet payment only. No mainnet network, mainnet USDC, production wallet, bulk retry, or automatic unattended payer is allowed.

The checked-in payer uses only the official low-level v2 client path: `@x402/core/client`, `@x402/evm/exact/client`, and `viem`, pinned in `package.json` to `2.25.0`, `2.25.0`, and `2.56.3`. It does not use the deprecated v1 `x402` package.

From the repository root, start the local server in one terminal with
`THEGRAPH_TOKEN` already injected by your secret manager:

```sh
npm run start:x402
```

After verifying the initial 402 and allowlisted requirements, use a second
terminal with the dedicated test payer's `X402_PAYER_PRIVATE_KEY` injected
by its secret manager. The following Base pool is inside the default
one-block evidence window:

```sh
npm run pay:assess -- 0xfa7714c40e1de3c702b8c8052230072d41f3f36f949bca2a26e9147d678a3c22 --network base
```

Run that command once only after approving the payment. Keep both secrets
out of command arguments, shell tracing, shell history and repository
files. The payer key must not enter the assessment server's environment.

`pay:assess` accepts only `http://127.0.0.1:4021/assess`, uses `redirect: "error"`, and signs only one matching v2 `exact` requirement: Base Sepolia `eip155:84532`, the documented test USDC asset, atomic amount `1000`, timeout `300`, and the public receiver in `config/assess-x402.mjs`. It exits before opening a socket if the payer environment value is absent or malformed. A signed retry is never repeated: a second 402 is `KNOWN_PAYMENT_REJECTION`; timeout, transport loss, another status, malformed settlement, or a missing transaction hash is `UNKNOWN_PAYMENT_OUTCOME`.

Only `HTTP 200` plus a successful `eip155:84532` settlement and a valid settlement transaction hash is a paid success. The CLI prints the HTTP status, network, amount, receiver, transaction hash, Base Sepolia explorer link, and assessment response; it does not print the key. For a new authorized round, preserve those public traces together with its assessment response. The 11 September round already has PASS evidence linked above; any new round needs its own outcome check.

For non-payment checks, run:

```sh
npm run test:assess-client
```

## Limits and current evidence

- The facilitator client has a 5-second timeout. Existing source calls remain bounded (Substreams 30 seconds; Token API 15 seconds per call); the HTTP assessment response has a 65-second ceiling.
- `THEGRAPH_TOKEN` can reach only the existing Base/Robinhood Substreams endpoints and the existing Base Token API path, after payment. It is not supplied to the facilitator.
- Offline evidence verifies an actual x402 402 before resolver work, malformed-payment gating, accepted-gate handler behavior, and invalid assessment input. The accepted gate is a test double, not a settlement claim.
- Real paid Base Sepolia acceptance is PASS for the recorded 11 September round linked above. Offline handler tests remain separate evidence and do not establish a new settlement.
